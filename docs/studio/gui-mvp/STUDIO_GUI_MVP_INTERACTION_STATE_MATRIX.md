# Studio GUI MVP Interaction And State Matrix

This document is the interaction contract for the fixture-backed Studio GUI MVP.
It exists so implementation, tests, visual QA, and future backend wiring all
share one understanding of what each visible state and command-backed
interaction is supposed to do.

The matrix is intentionally tied to the current fixture prototype:

- Source of truth for states: `STUDIO_MVP_REQUIRED_SCREEN_STATE_IDS` in
  `apps/studio/src/models/studio-fixtures.ts`.
- Source of truth for interactions: `studioCommandRegistry` and
  `studioCommandAvailability` in
  `apps/studio/src/commands/studio-commands.ts`.
- Source of truth for state transitions:
  `apps/studio/src/state/studio-state.ts`.
- Source of truth for visual behavior: the Studio GUI MVP specs and tracked
  visual references in `docs/studio/gui-mvp/` and `docs/assets/studio/`.
- Focused recovery invariant guidance:
  [`STUDIO_GUI_MVP_INVARIANT_TEST_RECOVERY.md`](./STUDIO_GUI_MVP_INVARIANT_TEST_RECOVERY.md).
- Non-editor surface polish guidance:
  [`STUDIO_GUI_MVP_NON_EDITOR_POLISH_DESIGN.md`](./STUDIO_GUI_MVP_NON_EDITOR_POLISH_DESIGN.md).
- Visible-control inventory:
  [`STUDIO_GUI_MVP_VISIBLE_CONTROL_AUDIT.md`](./STUDIO_GUI_MVP_VISIBLE_CONTROL_AUDIT.md).

The fixture MVP performs no real source writes, filesystem mutations,
credential use, provider deploys, or destructive history operations. Commands
with future source-write, destructive, or provider-mutation safety classes still
model the visible state changes, confirmations, disabled reasons, and
diagnostics expected from the future product.

## Universal Invariants

| Invariant                | Requirement                                                                                                                                                                               | Guarded by                                                       |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| Command centrality       | Toolbar buttons, menus, hotkeys, context menus, and command palette must dispatch shared command IDs. UI handlers may provide payloads, but they must not reimplement domain transitions. | `studio-command-state.test.ts`; command surface Playwright tests |
| Explicit availability    | A command that cannot run must return `disabled` or `blocked` with a human reason; blocked commands include a stable diagnostic code when a validation or capability issue is involved.   | `studio-command-state.test.ts`                                   |
| No silent mutation       | Failed, disabled, or blocked commands preserve the prior state and explain why they could not run.                                                                                        | `studio-command-state.test.ts`                                   |
| Fixture-only effects     | The MVP may update local fixture-backed app state only. It must not write project files, deploy, open broad filesystem access, or use credentials.                                        | reducer tests, publish/restore/media Playwright tests            |
| Preview truth            | The preview pane is a visual fixture view, not a second canonical Markdown renderer. Editing commands can mark it stale; preview commands can restore the ready fixture state.            | preview tests and implementation docs                            |
| Preview scope            | Article live preview exists only in article-editor states. The global Preview command opens a whole-site preview flow and must not reuse the editor live-preview toggle.                  | reducer tests and Playwright screen-transition tests             |
| Publish safety           | Publish must pass through preview, confirmation, apply/progress, and success/failure states. No direct publish shortcut may bypass preview and confirmation.                              | publish reducer and Playwright tests                             |
| Restore safety           | Restore must expose checkpoint selection and confirmation before the completed restore fixture state. Unavailable history is a capability state, not a broken UI.                         | restore reducer and Playwright tests                             |
| Invalid state prevention | Invalid article/settings inputs should block only the affected save/preview/publish action and show local field feedback plus actionable diagnostics.                                     | fixture validation, editor/settings tests                        |
| Hidden means hidden      | Hidden sidebar or preview states remove that region from the workspace layout. They must not leave a visible gray rail, label, focusable resize handle, or squeezed sliver.               | pane policy unit tests and Playwright visual checks              |
| Single selection         | Sidebar selection is derived from one active location. Opening an article selects only that article row, not both the article row and the Articles nav item.                              | sidebar selector tests and Playwright navigation checks          |
| Stable layout            | Sidebar, work pane, preview pane, toolbar, dialogs, and menus must keep usable minimum sizes, avoid overlap, and avoid document overflow at supported viewports.                          | Playwright layout tests and visual inspection                    |
| Accessible surfaces      | Dialogs, menus, tooltips, disabled explanations, status indicators, and navigation must expose semantic names and keyboard/focus behavior.                                                | Playwright accessibility tests and axe checks                    |
| Purposeful chrome        | Visible headings, helper copy, buttons, cards, and status panels must earn their space. Obvious screen descriptions and nonfunctional controls should be removed.                         | manual visual QA and targeted interaction tests                  |

`/?screen=<state-id>`. The rendered UI must show the intended screen without
legacy operation-dashboard chrome, document overflow, or inaccessible critical
controls.

milestone.

| `article.directory.resetFilters`    | Article directory.                                | Directory remains open with query/status/category/tag reset.                                                     | Disabled outside directory.                                                                     |
| `article.directory.setCategory`     | Article directory.                                | Directory remains open with `categoryFilter` payload and other filters preserved.                                | Disabled outside directory; serializable filter state only.                                     |
| `article.directory.setSearch`       | Article directory.                                | Directory remains open with query payload.                                                                       | Disabled outside directory; search is local fixture state.                                      |
| `article.directory.setStatusFilter` | Article directory.                                | Directory remains open with `statusFilter` payload.                                                              | Disabled outside directory.                                                                     |
| `article.directory.setTag`          | Article directory.                                | Directory remains open with `tagFilter` payload.                                                                 | Disabled outside directory.                                                                     |

## Flow And Interaction Invariants

| Flow                         | Required Interaction Chain                                                                                                 | Completion State                                                                                  | Regression Risk To Guard                                                                           |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| First launch to project home | `project.createSite` or `project.openSite` from startup/recent projects.                                                   | Project home with selected fixture project.                                                       | Accidentally requiring technical project-health steps before authors can start.                    |
| Missing project recovery     | `project.openSite` missing recent, then `recovery.locateProject` or `recovery.removeRecent`.                               | Located project opens home; removed project returns recent list without selected missing project. | Treating missing paths as fatal app errors or doing real filesystem mutation.                      |
| Article browsing             | `article.directory.open`, search/filter commands, `article.open`.                                                          | Selected article editor with correct preview readiness.                                           | Duplicated filtering logic or filters that survive reset incorrectly.                              |
| Article editing              | `editor.title.*`, `editor.properties.toggle`, `editor.updateSource`, formatting commands, `article.saveDraft`.             | Dirty/stale after edits; invalid title blocks affected actions; saved after valid draft save.     | UI-only mutations that bypass reducer or allow invalid saves.                                      |
| Media insertion              | `insert.image`, `media.open`, `media.setSearch`, `media.setViewMode`, `media.insertSelected`.                              | Article editor dirty/stale with Markdown image inserted.                                          | Inserting media without article/media context or losing alt text fallback.                         |
| Preview                      | `preview.open`, `preview.setViewport`, retry from failed/loading fixture states; disabled external-open affordance.        | Ready article/home preview and expanded pane, with visible desktop/mobile fixture viewport modes. | Preview becoming a second renderer, fake external-open success, or ignored invalid article blocks. |
| Publish                      | `publish.prepare`, `publish.openConfirm`, `publish.confirm`, `publish.finish`, `publish.done`; plus cancel/retry branches. | Return to editor/home after success or cancel; no active publish scenario.                        | Direct publish without preview/confirm, leaked credentials, real deploy from prototype.            |
| Restore                      | `article.restoreVersion`, `restore.selectCheckpoint`, `restore.confirm`, `restore.cancel`.                                 | Restored checkpoint fixture state or safe return to editor/home.                                  | Destructive restore without confirmation or unavailable history as a broken state.                 |
| Pane management              | `pane.toggleSidebar`, article-editor `pane.togglePreview`, resize handles.                                                 | Hidden panes are absent from layout; visible panes have usable minimums.                          | Sidebar sliver regressions, preview leaking onto non-editor screens, toolbar overlap.              |
| Command surfaces             | Command palette, toolbar dropdown, context menu, hotkeys, tooltips.                                                        | Same command IDs and availability reasons across all surfaces.                                    | Divergent command copies and stale disabled reasons.                                               |

## Component And UI State Invariants

| Component Area             | Invariants                                                                                                                                                                                    |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `StudioShell`              | Owns full-window shell only; no legacy operation dashboard chrome around the product UI; toolbar, sidebar, work pane, preview pane, and overlay layer are peers.                              |
| `AppToolbar`               | Shows navigation/search/status/actions without overlap; buttons expose names, shortcuts, disabled states, and useful tooltips.                                                                |
| `WorkspaceSidebar`         | Collapsible/resizable; expanded state is wide enough for nav and article tree; selected/expanded/tree actions are visible without color-only signals.                                         |
| `WorkspaceLayout`          | Enforces min/max pane sizes; hidden panes are absent from layout; resizing never creates negative, sliver, or overlapping panes.                                                              |
| `StudioWorkPane`           | Switches by `activeScreen`; each screen owns its empty/loading/error/dirty/invalid state instead of relying on generic placeholders.                                                          |
| `ArticleDirectoryScreen`   | View model drives search/filter/cards; no ad hoc source parsing; empty and no-result states are distinct.                                                                                     |
| `ArticleEditorScreen`      | Metadata descriptors drive forms; source editor commands route through reducer; invalid fields show local feedback and block only affected actions.                                           |
| `PreviewPaneShell`         | Shows article/home/status fixture views; route labels and diagnostics are explicit; collapsed preview is a real state with a recovery action.                                                 |
| `MediaScreen`              | Media grid/list and detail are fixture-backed; alt text feedback is text-visible; insert path requires article and selected media context.                                                    |
| `SettingsScreen`           | Descriptor-backed settings sections share form primitives; saved/dirty/invalid states are visible and local.                                                                                  |
| `PublishScreen` and dialog | Preview, confirmation, progress, success, blocked, and failed states are separate; credentials are redacted; focus remains inside modal while open.                                           |
| `RestoreScreen`            | Checkpoint selection, confirmation, completion, and unavailable-history states are separate and command-backed.                                                                               |
| Overlays and menus         | Escape closes the active command palette/menu where appropriate; focus returns to the invoking control; no overlay should remain after successful navigation unless it is the intended state. |

## Verification Matrix

| Verification Layer             | What It Must Prove                                                                                                                                                                                                                        |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Fixture validation tests       | Every required state exists, fixture references resolve, invalid/blocked states include diagnostics, media assets are local fixture assets.                                                                                               |
| Reducer/unit tests             | Command availability is explicit; blocked/disabled commands preserve state; representative interactions produce intended states; source editor transforms are pure; publish/restore/media/preview flows keep safety boundaries.           |
| Playwright state render tests  | Every required screen-state ID renders through the app shell with no legacy dashboard, no document overflow, and a screen-specific visible anchor.                                                                                        |
| Playwright interaction tests   | User-visible controls dispatch the same command-backed transitions as the reducer tests.                                                                                                                                                  |
| Playwright accessibility tests | Critical states pass axe checks for serious issues and expose semantic names, tooltips, focus behavior, and non-color-only diagnostics.                                                                                                   |
| Manual visual inspection       | Captured screenshots are compared against the GUI MVP visual references for overall shell composition, spacing, sidebar width, pane behavior, dialogs, directory/editor/media/settings/publish/restore screens, and obvious visual drift. |

## Accepted Prototype Limits

- The command matrix describes fixture behavior, not completed backend
  integration.
- Native window menus, real folder pickers, real file save/open, Cloudflare
  credential flows, and deploys remain future operation-backed work.
- Fixture-only safety belongs in command safety classes, tests, docs, disabled
  reasons, and confirmations. Routine product screens should not display
  prototype disclaimers or development-facing fixture copy.
- The preview uses fixture-rendered content to validate layout and flow, not a
  complete static-site build pipeline.
- WYSIWYG editing is out of scope for this milestone; the editor is a raw
  Markdown/MDX source surface with command-assisted formatting.
- The tracked generated and rough mockups are design references, not
  authoritative implementations.
